# 🐉 青龙面板日常签到小助手 (Qinglong-Daily-Scripts)

![Python](https://img.shields.io/badge/Python-3.8+-blue.svg)
![Qinglong](https://img.shields.io/badge/青龙面板-支持-success.svg)
![License](https://img.shields.io/badge/License-MIT-green.svg)

这是一个专为 [青龙面板](https://github.com/whyour/qinglong) 打造的日常自动化脚本库。主打**极简、稳定、防封**。
全部脚本基于纯 Python 编写，无需配置复杂的 Node.js 环境。

## 🌟 核心特色

* **零额外依赖**：只需安装最基础的 `requests` 库即可完美运行。
* **云端防风控**：部分高难度加密接口（如网易云）已剥离至第三方稳定云节点，彻底告别本地加解密报错。
* **消息精美推送**：内置 Bark 精美排版推送逻辑，运行结果一目了然。

## 📜 包含项目与功能

### 1. 📺 B站日常助手 (`bili_task.py`)
* [x] 每日账号登录检查与状态获取
* [x] 每日自动观看热门视频 (+5 经验)
* [x] 每日自动分享视频 (+5 经验)
* [x] **自定义投币机制**：可在脚本顶部自由设置每日投币数量（默认1枚），防止硬币被无脑榨干。
* [x] 执行结束报告显示任务前后经验值及本次经验变化

### 2. 🎵 网易云音乐全能打卡 (`netease_task.py`)
* [x] 手机端 + 网页端双端签到
* [x] 云贝中心自动签到，并检查、领取已完成的云贝任务
* [x] **黑胶 VIP 专属**：自动检查并领取已完成的成长值任务
* [x] **秒刷 300 首**：提交听歌活跃数据，助力账号完成听歌任务。

注意：云贝和 VIP 接口只能领取“已经完成”的任务。脚本会先执行签到、提交听歌记录，再检查可领取奖励；如果日志显示“没有已完成、可领取任务”，并不代表接口失效，而是该任务还需要对应的 App 操作（例如浏览、分享或推歌）。

## 🚀 青龙面板部署指南

### 第一步：安装依赖
进入青龙面板 -> **依赖管理** -> **Python3**，添加并安装以下依赖：
    
    requests

### 第二步：添加订阅 (拉库)
进入青龙面板 -> **订阅管理** -> 新建订阅：
* **名称**：`日常签到小助手`
* **类型**：`公开仓库`
* **链接**：`https://github.com/Han-cy77/Qinglong_auto.git`  
* **定时规则**：`0 6 * * *` （每天早上 6 点自动同步最新代码）

保存后，点击运行该订阅即可自动生成任务。

## ⚙️ 环境变量与多账号配置

请在青龙面板的 **环境变量** 中添加以下变量。脚本会自动识别单账号或多账号模式。

| 变量名称 | 说明 | 多账号支持 |
| :--- | :--- | :--- |
| `BILI_COOKIE` | **B站通行证**。网页端登录后 F12 抓取 `bilibili.com` 的完整 Cookie。 | **支持**。多个 Cookie 之间用 `&` 符号或换行符分隔。 |
| `NETEASE_COOKIE` | **网易云通行证**。网页端抓取，格式必须为：`MUSIC_U=xx; __csrf=xx;` | **支持**。多个完整 Cookie 请使用换行符分隔。 |

网易云脚本默认使用 `https://netease-cloud-music-api.fe-mm.com` 作为接口节点。如果该节点无法连接，可在青龙环境变量中增加 `NETEASE_API_BASE`，填入你自己部署或信任的兼容接口地址。脚本会把 HTTP 状态码、响应类型和响应片段写入日志，便于区分 Cookie 失效、节点不可达和接口返回异常。

### 👥 多账号配置示例

**网易云多账号：使用换行符**
在环境变量的值中，每行输入一个账号的完整 Cookie。网易云完整 Cookie 的 `P_INFO` 等字段可能含有 `&`，因此不能用 `&` 分隔账号。

**B站多账号：**仍可用 `&` 或换行符分隔。

## 🧵 并发执行与独立日志

为提升多账号执行效率，脚本已重构为**多线程并发模式**：

1. **并发执行**：
   * 脚本会自动检测环境变量中的账号数量。
   * 默认启用 3 个并发线程同时执行任务，单个账号失败不会影响其他账号。

2. **独立日志记录**：
   * 每次执行都会在 `logs/` 目录下生成独立的账号日志文件。
   * **命名格式**：`任务名_账号名称_日期.log`
     * 示例 1：`Bilibili_Account1_123456_20231027.log`
     * 示例 2：`Netease_MyNickname_20231027.log`
   * 方便用户单独排查某个账号的执行情况。

## 💻 命令行使用示例

如果你喜欢在本地终端或 SSH 中手动运行，也可以通过设置临时环境变量来调用：

**示例 1：单账号执行**
```bash
# Windows Powershell
$env:BILI_COOKIE="你的Cookie"; python bili_task.py

# Linux / MacOS
export BILI_COOKIE="你的Cookie" && python3 bili_task.py
```

**示例 2：多账号并发执行**
```bash
# Windows Powershell
$env:BILI_COOKIE="Cookie1&Cookie2"; python bili_task.py

# Linux / MacOS
export BILI_COOKIE="Cookie1&Cookie2" && python3 bili_task.py
```
*(注：执行后控制台将显示汇总报告，详细日志请查看 logs 目录)*
